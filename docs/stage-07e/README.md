## 数据与访问

公开代码和截图使用独立样本场景，不能据此认定真实商业合作或测试结果。实际附件未提交。真实数据只在受控本机运行时加载，不随生产构建分发，不保存至 localStorage/sessionStorage。

```sh
# 需要 Python + openpyxl；输出路径只能在仓库外或被忽略的 private-data 内
python scripts/import-business-data.py /absolute/source.xlsx /absolute/private/data.json
MAAS_PRIVATE_DATA=/absolute/private/data.json npm run dev -- --host 127.0.0.1
```

原件包含资源同步、采购需求、供应商测试三张表。按白名单字段导入名称、模型资源、需求及原始测试阶段；凭据列不读取，URL、疑似密钥和长认证串会被排除。不要把原件移入 `public/`。本机服务拒绝非回环、代理转发及非本机 Origin 的私有数据请求，Vite 拒绝直接读取私有目录或 Excel。该入口不提供远程共享或正式鉴权服务。

名称只合并大小写一致的重复项，不猜测别名对应的公司全称。全称缺失时保留原始名称，简称仅去除公司类型后缀；仍需要采购校对。多公司混写、银行和证明文件片段不建立主档。无渠道且业务域未知的档案由有维护授权的采购查看，未扩大运营业务域权限。

测试通过只采用明确的第一阶段通过字段；第二阶段“已完成”不等于通过。历史结果不伪装成新的已核验执行。为历史渠道保留两阶段待办骨架，未建立生产配置或已生效合同。无法确定的负责人、联系方式、合同、凭据、执行报告与日期留空或待补充。缺失折扣在界面显示待补充。采购候选仅按完全相同模型名称关联，不推断商务适配或可调度结论。

HTML 原件仅参考统计周期、模型规格及用量/收支明细的信息分层，未把客户经营数据作为本系统真实业务事实。

## 仍需产品反馈

历史资源需要人工确认交付节点和岗位交接，因此流程完成度可能仍为 0%；这与原始质量测试状态分别显示。模型复合名称尚未拆分，简称与法人全称的别名关系、真实联系人、负责人和需求匹配需要业务校对。原件不提供足够合同证据，内部模式不编造合同进度。正式多用户权限和远程受控演示仍需后端支持。

三种岗位检查：采购可从需求定位候选与资源目标；产品运营可在渠道抽屉推进并核对卡点；测试可从任务进入执行，并由整改进入复测。复杂核验继续保留原有安全步骤。默认列表已减少解释和重复摘要，详细技术记录保留在抽屉及历史中。

内部导入模式的修改仅保留在当前会话，刷新后恢复导入资料；需要跨会话保留的正式演示应接入受控后端。缺少实际执行记录的历史“测试中”状态仅作快照，后续执行需开启新轮次，不补造运行记录。
