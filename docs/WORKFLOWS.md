# 第 01 阶段状态与流转边界

基础词汇定义在 `src/domain/statuses.ts`，每个状态都有独立中文映射。

| 维度           | 稳定代码                                                       |
| -------------- | -------------------------------------------------------------- |
| 采购寻源       | draft / sourcing / gap / matched / closed                      |
| 渠道质量测试   | pending / running / passed / failed / exempted                 |
| 渠道连通性测试 | pending / running / passed / failed                            |
| 渠道接入       | not_started / integrating / integrated                         |
| 渠道开放       | closed / open / suspended                                      |
| 报价           | reference / pending_contract / effective / temporary / expired |
| 供应商整改     | open / in_progress / submitted / closed                        |
| 供应商事件     | reported / investigating / resolved / closed                   |

另有 TestTask.status = pending/running/completed/cancelled；执行 result = passed/failed/inconclusive/null。任务完成不等于测试通过，执行结果不会自动改变接入/开放状态。Demand 与 DemandItem 分别记录寻源状态。

以上是第 01 阶段基础词汇，不是已审批的完整状态机。不提供任意改状态的写接口，不凭空增加审批路径。详细可流转边、角色、条件、回滚和并发策略全部 TBD。

已实现的纯规则边界：

- `canExemptQuality` 要求官方原厂类型、来源已核验及独立证据；其他渠道不豁免。具体证据核验标准 TBD。每个渠道独立连通性任务，即使质量豁免也保留。
- `appendQuote` 追加版本，新 ID 不重复；正式价需确认信息，促销需起止区间，更正需原因与原报价 ID；不覆盖旧记录。不提供最终有效价格选择或合同审批。
- `bindOpChannelId` 只接受初始绑定或相同值，不允许覆盖；纠错流程 TBD。
- `supplierCoverage` 计数不同供应商并报告资源缺口，不把“三家”变成硬约束。

一任务多执行，每次独立 ID；原执行不覆盖。质量与连通性互不代替，也不默认固定先后顺序。报价状态不等于渠道状态，正式合同历史、新待确认报价和临时优惠可同时存在。

TBD：寻源审批、资源匹配判定、报价合同签署、测试重试/核验失效、整改关闭条件、事件升级、渠道接入准入、开放门禁、审计保留期。当前仅有只读工作台与模块占位，没有真实写入或生产工作流。

## Stage 03：主档交互

- 运营从供应商列表新增：校验必填、目录负责人、邮箱及唯一性 → 生成内部 UUID、默认启用和版本 1 → 追加创建审计并保存 → 成功后进入详情。无需渠道；保存失败留在表单，不提示成功。
- 编辑授权主档：展示现有值 → 提交原 version → 再次鉴权并校验 → 有变化才生成新版本与 before/after 审计 → 刷新列表/详情。若 version 不一致，拒绝保存，必须显式重新加载；不自动覆盖。
- 负责人分配：仅运营调整；负责人必须是模拟采购用户。主档 ID 不变，维护授权转移，生成 owner_assigned 记录；渠道、测试、接入和开放状态均不改。
- 启停：运营二次确认，只改变主档 status 并留痕。停用提示不再作为新增采购合作默认选项；本期未开发新增采购流程，不实现级联删除或自动禁用渠道。恢复启用保留 ID、关联资源及历史。
- 合作状态与启用状态独立可编辑，不自动互相推导。无物理删除、外部邀请、报价录入或测试结果提交。
- 重置：双域运营全部域视角确认后，恢复初始供应商、主档管理范围、采购维护授权和创建历史；不触碰报价/渠道/测试/事件 fixture。

localStorage 读取失败、数据版本不兼容时显示可理解错误，不自动清除存量。可重试读取或由有权运营确认重置。持久化失败不提交内存状态。TBD：真实后端事务、跨窗口原子并发、数据迁移与组织授权审批。

## Stage 04B：渠道主档操作（仅 Mock）

1. 产品运营进入 /channels，点击“新增渠道”，从当前供应商主档和授权模型目录选择关联，填写类型、名称及选填能力/非敏感引用。
2. Adapter 验证身份、域、启用供应商及输入，生成稳定 ID；一次保存渠道、两条待测试任务和创建历史，成功后进入详情。失败保留表单及错误，不制造部分关联。
3. 详情“编辑基础信息”只维护白名单字段。按加载时 version 保存；冲突提示重新加载（可取消抽屉并点击“刷新资料”），不覆盖他人修改。关联对象及技术状态不在普通编辑范围。
4. “启用/停用资源主档”单独二次确认，仅改变 resourceStatus，不执行真实 OP 变更或上线/下线。
5. 未绑定渠道可输入 MOCK- 开头的模拟 OP ID，先预览前后值，再确认。保存边界复用全局绑定唯一性规则；不同渠道冲突拒绝、已有其他绑定不可覆盖、相同绑定重复确认幂等，不联动测试/接入/开放状态。
6. 所有已有模块重新查询时读取同一 Repository，无独立渠道副本。新建后的模型/供应商覆盖和工作台任务指标同步；没有报价和执行的渠道返回空历史。
7. 重置渠道需独立二次确认，明确清除新增渠道/任务/渠道变更记录，保留供应商。若新增渠道引用本地新供应商，供应商重置先被阻止；先确认渠道重置，再单独确认供应商重置。损坏/不兼容渠道数据提示恢复，只有明确确认的渠道重置才覆盖它。

不执行采购调价、寻源、质量/连通性测试、OP 真实配置或开放上线。停用供应商的新合作例外、关联迁移、OP 解绑/重绑仍为 TBD。

## Stage 05A：需求与候选的最小流转

运营从 /sourcing 新建：分别填写运营受限信息与采购共享内容，可不关联客户；添加一条或多条授权模型明细、整数基点折扣与能力/地区限制。模型必须全部授权。保存按单次创建请求幂等标识生成稳定主单/明细 ID 与可读模拟编号，一次提交并进入 /sourcing/:demandId；失败保留表单，禁止部分提交或虚假成功。已有明细模型不可普通迁移/删除，可维护要求并追加明细。

运营和采购可在开放状态的授权明细添加候选（包括草稿，记录候选不自动推进主单状态），从当前渠道目录按供应商/类型/能力/资源及四个技术状态筛选；只允许同模型且当前获准读取的渠道。一次添加一条，可连续录入多家或同供应商多渠道。所有判断依据和跟进说明明确为采购共享文本，不得包含客户身份/售价。

候选初始 candidate，人工可修改为 suitable/unsuitable/excluded 或重新评估为 candidate，每次保留原 ID 和前后差异。无物理删除；已有关系不能重复添加。辅助判断不会自动更改人工状态，也不代替测试/询价。渠道能力或启用变化后按最新资源重新判断，历史关系仍保留。

主单状态流转由统一 sourcingTransitions 定义：

| 当前     | 允许人工流转                |
| -------- | --------------------------- |
| draft    | sourcing / closed           |
| sourcing | gap / matched / closed      |
| gap      | sourcing / matched / closed |
| matched  | sourcing / gap / closed     |
| closed   | 无，全部寻源写入终止        |

运营/采购每次推进需共享说明，完整明细域授权和原 version。matched 需每条明细当前至少三家人工初步符合且无明确能力不符的启用资源供应商；gap 需至少一条明细不足三家，由人工明确表示已调查确认；零候选也只有明确推进 gap 后才表示已确认不足。已匹配或缺口仍可调整候选并留痕；计数变化不自动改主单状态或合同/渠道状态。关闭是本期终止态，不开发重新开启或审批链。

编辑、候选、进度均采用主单 version；任何候选变化会使旧主单表单失效。冲突显示重新加载提示，用户取消表单后点击“刷新需求”，不自动覆盖。无实质修改不写入、不增版本、不追加空历史。

重置顺序：若新增渠道被候选/排除历史引用，渠道重置先拒绝；双域运营先二次确认“重置寻源演示数据”，再独立确认渠道重置；若还有新增供应商关联，再依既有规则单独确认供应商重置。每一步明确清除范围，其他模块不静默级联清空。无需重置浏览器即可在重新查询后看到一致统计。Stage 05B 未开始。
