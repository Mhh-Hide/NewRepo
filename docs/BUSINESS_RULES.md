# 已确认业务原则

1. 模型由厂商提供，同一模型可有多个供应商。
2. 一个供应商可以提供多个模型。
3. 同一供应商针对同一模型可以有不同渠道类型。
4. 渠道是报价、测试、接入管理的最小操作单元。
5. 每条渠道具有独立且不可重复的内部渠道 ID。
6. OP 渠道 ID 单独存储，允许初期为空。
7. 质量测试和连通性测试是两个独立阶段。
8. 所有渠道都需要连通性测试。
9. 经核验的官方原厂 Key 可按规则跳过质量测试；核验标准与豁免细则待确认。
10. 供应商报价区分参考报价、正式价格、临时优惠。
11. 已确认价格变更必须保留历史记录。
12. 报价、测试及关键状态变更需要操作审计。
13. 国内/海外业务域按模型厂商归属划分，不按模型销售地区划分。
14. 采购不能查看客户身份及客户售价。
15. 测试不能查看客户身份及客户售价。
16. 运维可以查看客户与供应商身份，但不能查看任何客户售价及采购商业折扣。
17. 供应商只能访问自身授权数据。
18. 产品运营能够查看完整业务数据。
19. 前台人员不能查看供应商真实身份。
20. 后续销售、总监、VP 三档价格同时展示给有权限的前台人员；用户等级影响报价权限，不影响三档价格可见性。本期不开发。

本阶段仅记录，不实现上述业务。价格币种、计价单位、有效期、精度、确认流程、审计保留周期待详细 PRD，不自行定义。

## Stage 05A：寻源规则（仅本期授权）

- 主单至少一条授权模型明细，可包含不同模型及业务域；创建时每个模型都必须在操作人和当前选中域的交集中。域仍按厂商推导，地区限制不会扩大权限。
- 标题、说明、客户关联为运营受限内容；共享标题、摘要和技术要求独立录入，禁止从运营原文自动复制或以关键词替换假装脱敏。客户不是必填项。
- 同一明细只关联对应 modelId 的当前授权渠道。可关联同供应商多渠道，但覆盖按 supplierId 去重。既有关系不物理删除，excluded 不计当前候选，仍显示历史并可重新评估。
- assessCapacity 只作辅助：TPM/RPM/并发须不低于需求，TTFT 不高于上限；任一已知不满足或渠道停用为明确不符；需求/能力缺失、尚无要求、地区限制待核实为信息不足。不使用测试通过作为全部能力满足依据，不自动设置人工匹配状态。
- 人工 suitable 必须填写共享依据，当前明确不符或停用的渠道不能新标记 suitable；历史 suitable 在渠道停用后仍保留原记录，但不计当前初步符合覆盖。信息不足可由人工初步判断并说明依据，此数量不是自动验证通过数，仍需继续核实。
- 目标为每明细三家人工初步符合、当前启用且未发现明确能力不符的不同供应商；不足三家仍可保存。主单不能仅因计数自动变为已匹配或采购完成。
- 区分阶段：零关联为尚未开展；有候选无初步符合为待核实；人工初步符合不足三家为覆盖不足；gap 状态下不足三家的明细为人工已确认不足；达到三家仅为初步覆盖达标。数学差额不等同已调查结论。
- 缺口主单统计：未关闭且至少一条当前授权明细“有寻源关联记录或主单人工标记 gap”且距三家大于零；无候选且未标记 gap 的明细不计入。候选待核实会计作覆盖不足，同时单独标明阶段。列表和 Dashboard 使用同一规则；人工 matched 状态与当前数学覆盖独立，资源变化后可能同时计入“已匹配”和“存在覆盖缺口”，不自动覆盖历史结论；原初始全域缺口从 2 改为 1，因为草稿零候选不再自动当作已开展缺口。
- 主单资料、状态写入要求所有明细业务域完整授权；混合域需求在单域视角只读当前明细，仍可维护当前明细的获准候选。已关闭主单全部写入终止。无采购负责人字段，不擅自推断认领/组织分配；精细需求授权及负责人流程 TBD。
- 本期不录入报价、签署合同、采购定价、自动选供应商、执行测试或变更 OP。

## Stage 05B：报价与价格口径

- 采购目标 targetPurchaseDiscount 与上游实际 discount 不覆盖、不自动同步。报价必属一个稳定内部渠道，供应商/模型不得手工填写不一致值；日常报价可无需求或询价。
- 录入允许 reference/pending_contract/temporary；正式 effective 必须独立模拟确认。promotion 与 temporary 对应，优惠必须有起止和 mock: 证据，不能覆盖正式长期记录。correction 可更正对应类型，但必须有同渠道前序及原因。
- A 原始供应商报价、B 内部来源核验、C 正式依据模拟确认分别记录。采购和运营可录入/核验，只有运营可正式确认；正式确认要求独立核验、非优惠的参考/待合同状态、有效生效时间、依据、确认人/时间及说明，已结束报价不能确认。Demo 不代表真实合同签署，不建立集团审批链。
- 时间有效性独立于记录状态：已到期/尚未生效/有效期内/未提供。截止时间不含，结束记录保留历史；正式和临时数量仅计有效期内，待确认/参考数量排除已到期。七天内到期优惠仅计当前有效且未来7天内截止的记录。最近七天有报价渠道按创建时间窗口和渠道 ID 去重。
- 每条保存报价永不原地改价、删除或将纠错混成供应商调价；确认与核验追加事件，历史更正追加新报价并保留父链接。多条正式/临时/参考记录可并存，**不计算唯一当前结算价或自动优先级**。
- 对比要求模型、币种、价格基准、适用规格、计量维度/数量/单位、记录状态及适用有效期一致且关键口径非空，否则列出不可比原因。Input/Output、千/百万、文本/视频、不同币种不能混比，不自动换算汇率或推断官方刊例价。折扣差只显示基点，不当作节约比例，不自动推荐采购渠道。
- Stage 05A 采购目标尚未有价格基准/规格元数据，本期保持其存储格式，在寻源详情与报价并列展示并明确不可直接比较，不计算目标达标差价，也不改变 suitable/采购完成状态。
- 询价是人工台账，不发送外部消息。draft 可到 sent/closed，sent 可到 quoted/closed，quoted 可到 closed，closed 不重开；同状态可追加不同跟进说明。录入回复可原子标 quoted，核验与正式确认仍独立。收到报价不是已核验。
- 供应商/渠道停用保留历史，本阶段记录历史商业资料不表示授权新的合作、上线或采购决策。真实合同、结算精度/舍入、折扣基准目录、供应商门户、促销优先级及关闭重开仍待确认。

## Stage 06A：可信采购价格分析

- 所有分析从当前授权报价/询价与渠道、供应商、需求数据计算，查询不写入、不缓存第二套价格状态。模型域仍按厂商推导。普通模型/供应商/渠道/厂商/状态/币种/北京时间创建日筛选影响报价指标；询价只按渠道相关范围筛选，报价状态/币种/创建日不限定询价。
- 有报价模型、渠道、供应商分别按稳定ID去重，多渠道不能算多家。正式记录渠道数/优惠记录渠道数含历史；当前有效正式价需确认人、有效确认时间及已开始/未截止的区间，当前有效优惠同样排除未来和到期。参考/待确认排除已到期及异常有效期。已到期单独统计，观察口径有重叠，不允许相加当供应商数量。
- 未来7天到期优惠窗口为 (查询时刻, 查询时刻+7×24小时]，均展示北京时间；仅当前有效优惠进入提醒。Dashboard沿用Stage05B同一窗口/去重口径，新增待跟进链接，不发送通知。
- 同模型渠道独立列最近报价（按记录创建时间）、最近已确认正式记录（同样按报价创建时间）和所有当前有效优惠；最近不等于唯一成本。普通筛选限定上述记录范围，但“正式记录并存”提示检查同一授权渠道的完整历史，不按币种/日期过滤后误报不存在。
- 横向比较复用 compareQuotes 的相同模型/完整币种/基准/规格/计量数量单位/状态/有效期条件；未知和异常有效期拒绝可比，不推测单位、刊例价、汇率、最低价或供应商排名。
- 历史趋势按渠道、完整币种/基准/规格/计量数量单位和原录入状态分组。历史适用期本可变化，趋势只观察同口径记录折扣，不声称跨有效期商业采购可比；横向比较仍要求完全相同有效期。确认事件不新增点，也不因投影状态变化把原录入参考/待确认记录移动为另一种原始调价事件。纠错点单列菱形，不接入供应商真实调价线；不足两条非纠错同口径记录不连线，说明原因。X轴明确选创建时间或供应商报价时间，缺失不以录入时间冒充。
- 采购目标仍无基准/规格元数据，只显示报价减目标的整数基点数字差，固定标注“同基准可比性未确认”；verifiedTargetRate/verifiedAchieved保持null，不算真实节约额，不改目标、匹配状态或采购结论。
- 询价“已发起（未关闭）”仅当前sent/quoted之和；draft单列，closed单列，不假设关闭前曾发送。待回复仅sent；已收到仅quoted；逾期仅sent且已知截止早于查询时刻，未知不补零。现有requestedAt是台账登记时间，supplierQuotedAt是报价日期，均不等于实际发送/回复时间，responseHours为null。
