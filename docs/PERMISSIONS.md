# 第 01 阶段权限模型

实现位置：`src/auth/types.ts`、`policy.ts`、`projections.ts`、`view-models.ts`；记录访问控制位于 `src/mocks/mock-adapter.ts`。先校验动作和记录范围，再以显式字段白名单生成 ViewModel，不是 React 隐藏字段。返回对象中未授权字段不存在，包括嵌套对象；不是填 undefined 或替换成星号。

| 活动角色          | 供应商身份 | 客户身份   | 采购折扣/目标 | 客户售价   | 读取范围与职责                                   |
| ----------------- | ---------- | ---------- | ------------- | ---------- | ------------------------------------------------ |
| ProductOperations | 可见       | 可见       | 可见          | 可见       | 已授权业务域完整业务信息，运营管理               |
| Procurement       | 可见       | 不可见     | 可见          | 不可见     | 域内授权供应商、采购需求及报价；可登记事件       |
| Testing           | 可见       | 不可见     | 不可见        | 不可见     | 域内技术参数、测试及整改                         |
| OperationsSupport | 可见       | 可见       | 不可见        | 不可见     | 域内需求和供应商事件；可登记异常，不管理接入流程 |
| SupplierUser      | 仅自身     | 不可见     | 不可见        | 不可见     | 域内自身供应商、模型/渠道、测试结论和整改        |
| Sales             | 不可见     | 仅授权客户 | 不可见        | 本期不返回 | 域内脱敏资源能力及授权客户需求                   |
| AccountManager    | 不可见     | 仅授权客户 | 不可见        | 本期不返回 | 同销售                                           |
| SolutionArchitect | 不可见     | 仅授权客户 | 不可见        | 本期不返回 | 同销售                                           |

默认拒绝：未选择演示用户时所有业务列表为空、详情 null；未知用户报错。权限使用确定的角色字典；未授予动作不访问。无业务域授权即无业务记录，运营也不能绕过。未命中的详情/猜测的 ID 同样不可访问。供应商/采购额外要求 UserSupplierGrant；前台需求额外要求 UserCustomerGrant。所有角色均通过模型厂商确定业务域，不设“国内采购/海外采购”角色。

供应商主档无业务域，通过可访问渠道判断主档是否在当前范围（没有可访问渠道的供应商默认不返回）。供应商用户不能借模型查询、任务 ID、执行 ID、整改过滤获取别家信息。供应商级事件通过供应商域内渠道判定可见，渠道级事件额外检查该渠道范围。无渠道主档及供应商级事件的未来授权策略 TBD。

字段策略：供应商联系方式与采购负责人仅运营、采购和该供应商自己可见；测试、运维仅见身份摘要。前台渠道不含 supplierId、OP ID、Endpoint 引用、实际调用名及原始 displayName，生成含稳定匿名代号的模拟资源显示名，禁止按隐藏 supplierId 筛选形成探测渠道。前台可见模型、渠道能力与独立状态，不返回供应商主档。

采购需求不含 customerId、客户对象、requesterUserId；只含脱敏主单标识、明细、采购目标和授权候选渠道。运维需求含客户身份但不含售价和采购目标。审计含敏感快照，仅授权域产品运营可查询；其他角色不能用审计绕过字段规则。报价接口仅运营/采购；供应商本阶段也不返回商业折扣，未来报价填报权限另议。

测试报告外部引用、任务分配与内部操作人仅内部技术角色可见；供应商只见自身测试结果与整改内容。自由文本当前均为受控模拟内容；生产环境必须另行制定备注、报告、审计中的敏感内容和附件隔离策略。

PermissionAction 包含读取和未来维护意图：supplier:maintain、demand:process、quote:maintain、incident:record、operations:manage；本期无写入接口，不代表已有业务流程。产品运营拥有管理意图；采购维护授权供应商/需求/报价并登记事件；运维可登记事件。其余未明确写权限拒绝。

销售价格等级 sales/director/vp 与角色独立；本期不返回三档价格、不开发审批。未来三档可见性不受本人等级影响，等级只影响报价授权。

**Demo 安全限制**：`createMockAdapter(userId)` 只是演示身份选择器，不是登录凭证或生产认证。Mock 数据会位于前端代码中；开发工具可读取原始夹具，所以不能放真实敏感信息。API 响应过滤不代表生产安全，后端必须强制鉴权、行级/字段授权和审计。返回深拷贝防止客户端改动污染夹具。

TBD：多角色合并、跨域主档维护、导出/附件访问、真实租户隔离、前台客户授权分配、角色管理，以及供应商后续写入权限。

事件记录范围沿用原规则，不新增角色权限。listIncidents 先过滤业务域、供应商及渠道，再调用 projectIncident，深拷贝 SupplierIncidentView；不直接返回原实体。

其余角色仍无事件查询权限。采购与运维保留 incident:record 动作声明，本期仍无写 API 或编辑页。摘要仅接受稳定分类代码并映射固定文本，未知代码回退为“模拟其他事件”；不进行关键词替换，不尝试从受限全文自动提取安全内容。投影使用逐字段白名单，对新增未分类字段默认不返回；customer 内部也只选择 id/name。

生产 TBD：摘要必须通过受控分类或独立审查，不能允许用户把秘密自由填写进公开摘要；混合全文暂仅产品运营可读，生产分类录入、复核、最小授权及再分类流程仍需确认。附件正文、文件名、下载 URL、报告、备注、导出与审计快照须有独立后端鉴权、分级、持久化与访问审计，不能依赖前端投影保密。Demo 夹具仍完全虚构且可被浏览器工具读取。

前台渠道现通过稳定 anonymousCode 区分，显示代号不取自供应商名称或 shortCode；原始 displayName、supplierId、Endpoint 等字段策略不变。未来正式匿名代号分配、跨系统关联和防推断策略 TBD。

## Stage 03：主档授权与维护权限

本节替代旧“无渠道供应商一律不返回”的限制，其余字段、客户、商业信息及渠道业务域规则保留。主档授权、渠道域授权、采购维护授权是不同关系。

| 角色                         | 主档读取                                   | 编辑资料           | 新增 / 调整负责人 / 启停 | 主档历史     |
| ---------------------------- | ------------------------------------------ | ------------------ | ------------------------ | ------------ |
| 产品运营                     | 当前管理域授权主档；或既有可见渠道对应主档 | 授权主档           | 授权范围内可操作         | 授权主档可见 |
| 采购                         | 明确维护授权主档，允许无渠道               | 仅明确维护授权主档 | 不允许                   | 授权主档可见 |
| 测试 / 运维                  | 既有授权渠道关联的身份摘要                 | 不允许             | 不允许                   | 不返回       |
| 供应商用户                   | 仅静态所属的自身主档，允许无渠道           | 不允许             | 不允许                   | 不返回       |
| 销售 / 大客户经理 / 解决方案 | 不返回                                     | 不允许             | 不允许                   | 不返回       |

所有读取均要求至少一个当前有效业务域授权。产品运营新建主档的管理范围来自自己的授权域与当前筛选；它不表示供应商只能供应这些地区模型。采购通过明确维护授权读取主档，不依赖渠道或主档管理域；因此被分配的采购可能在本域看到一个关联渠道数为 0 的主档。详情技术摘要仍由同一 Adapter 的渠道授权过滤后计数，不能越权读取其他域。

本期主负责人调整同步转移采购维护授权。渠道对采购的供应商范围采用最新维护关系，再与原厂商业务域相交；不会越过其业务域，也不会修改任何渠道数据。供应商用户所属关系、事件及其他原权限不因主档更名或启停自动改变。

新增动作 supplier:create、supplier:assign、supplier:toggle、supplier:history、demo:reset 由现有 can 策略定义。supplier:maintain 保留，写服务还会再次检查当前记录、最新维护关系、版本和会话写标记，不信任 UI 按钮或旧 capabilities。角色/业务域切换会使旧 DemoSession 的写标记失效；这是演示隔离，不是真实认证或服务端会话。

字段：测试/运维只返回名称、缩写、类别、合作/启停状态、注册地区、版本与时间摘要；不返回联系人、负责人、简介和内部备注。供应商用户可见自身基础联系资料及简介，不见内部备注、创建/修改操作人、账号预留状态和历史。产品运营和采购可见授权主档管理资料，但供应商 API 从不包含客户身份、客户售价、采购折扣或真实凭据。主档历史仅运营/采购可读，before/after 仍显式投影，不返回原始仓库对象。

全局“重置演示数据”仅双域授权产品运营在全部业务域视角可执行，需二次确认；避免单域人员重置不可见数据。普通资料编辑不能覆盖/删除审计，只有专用演示重置恢复初始资料及历史。

生产 TBD：内部备注和简介的保密录入/复核、联系人隐私、附件与导出鉴权、多人采购维护、跨部门管理范围，以及真正后端授权/事务/审计。禁止在演示表单填写真实敏感内容；字段投影与 localStorage 都不提供生产保密能力。

## Stage 04A：模型资源池与渠道只读详情

继续使用原身份/业务域/供应商维护及所属授权，未新增角色、放宽字段策略或修改主档写入逻辑。资源查询只组合已授权 listVendors、listModels、listChannels、listSuppliers；不返回原 Store，不调用报价或受限审计接口。

- 运营：查看授权业务域资源及关联的供应商身份。
- 采购：模型目录按原业务域授权；渠道继续受最新采购维护关系与厂商业务域共同约束。原报价权限由原接口保留，资源接口本身不返回任何价格。
- 测试/运维：复用既有技术/状态授权及供应商身份摘要，不返回采购商业信息、客户信息或主档联系资料。
- 供应商：仅自身渠道和由其渠道关联的模型，猜测其他渠道/模型 ID 返回 null。
- 销售、大客户经理、解决方案：仅匿名渠道与授权模型；不读取供应商主档，不返回 supplierId、供应商身份对象、缩写、联系资料、覆盖家数、OP ID、Endpoint 引用、实际调用名或来源核验技术字段。匿名代号继续由原 projectChannel 生成。

内部技术字段仅从已有 ChannelView 投影按属性存在性复制，没有给新页面额外授予读取权限。来源核验等字段若原角色没有授权，也不返回。模型/渠道详情先在授权目录中匹配 ID，不存在与无权访问统一返回 null，页面给通用说明，不回显未授权记录。

前台带 supplierId 或 supplierCoverage 参数时明确拒绝并可清除筛选，不允许通过覆盖条件推断隐藏供应商。厂商选项只来自授权目录，手填其他域厂商 ID 也不能扩展结果。

供应商覆盖只附 id/name/shortCode/status，任何角色的资源查询都不附联系人、内部备注、客户售价、采购折扣或原始审计；获准查看更多主档资料的角色可自行导航至原供应商详情。主档独立授权与渠道域授权继续分离：能看见一个主档不代表能看见其所有域的渠道。

只读页面仍是 Mock，浏览器工具可读取编译后的虚构 fixture；不能当作生产鉴权。真实后端行/字段授权、匿名代号策略与接入接口仍待独立任务确认。

## Stage 04B：渠道写入边界

新增五个独立动作：channel:create/update/toggle/bind-op/history，仅产品运营拥有，不从 supplier:maintain 推导。每次写入检查当前会话有效性、角色、渠道可见范围、业务域及版本；切换身份/域后保留的旧 API 引用不能写入。创建只接受当前域授权模型及当前主档内已启用且获准的供应商。无域运营不能写入。

| 角色                       | 渠道读取               | 主档新增/编辑/启停 | 模拟 OP 绑定 | 渠道变更历史   |
| -------------------------- | ---------------------- | ------------------ | ------------ | -------------- |
| 产品运营                   | 授权业务域             | 允许               | 允许         | 允许，按域过滤 |
| 采购                       | 明确维护供应商和授权域 | 拒绝               | 拒绝         | 拒绝           |
| 测试、运维                 | 原授权资源             | 拒绝               | 拒绝         | 拒绝           |
| 供应商                     | 仅自身及授权域         | 拒绝               | 拒绝         | 拒绝           |
| 销售、大客户经理、解决方案 | 授权匿名渠道           | 拒绝               | 拒绝         | 拒绝           |

技术字段沿用既有 internalMetadata 权限；channelAccess 返回字段级可见性元信息，即使列表为空也不靠首行推断。前台仅使用稳定匿名渠道代号，不提供供应商筛选或 OP 绑定筛选，不返回供应商名称/缩写、OP ID 和技术引用。历史快照不向非运营角色返回，不能绕过原投影取得原始渠道。没有客户资料或价格新增接口。

重置限双域产品运营在“全部”域执行并二次确认。渠道重置保留供应商；供应商重置检查全部渠道依赖，拒绝不安全操作。Mock 存储、身份选择与客户端权限均不是生产安全；真实后端仍须执行权限、字段投影与事务。已有自由文本/附件保密待办继续有效。

## Stage 05A：内部采购寻源权限与字段投影

新增独立动作 sourcing:read/create/update/match/progress/history。运营拥有全部动作；采购只有 read/match/progress/history，不能从 supplier:maintain 推导需求创建或资料编辑。需求本期按角色与模型业务域授权；采购候选渠道进一步沿用现有维护供应商范围，不扩大渠道读取权。

| 角色                       | 内部寻源列表/详情    | 创建/维护业务需求    | 候选/人工状态/跟进                       | 客户及受限说明                     | 采购目标 |
| -------------------------- | -------------------- | -------------------- | ---------------------------------------- | ---------------------------------- | -------- |
| 产品运营                   | 授权域               | 完整主单域授权时允许 | 授权范围允许                             | 允许                               | 允许     |
| 采购                       | 授权域共享视图       | 拒绝                 | 明细候选按域与渠道范围；主单进度需完整域 | 拒绝                               | 允许     |
| 测试、运维                 | 拒绝内部商业详情     | 拒绝                 | 拒绝                                     | 不从本接口提供                     | 不提供   |
| 供应商                     | 拒绝内部寻源数据     | 拒绝                 | 拒绝                                     | 不提供                             | 不提供   |
| 销售、大客户经理、解决方案 | 仅保留原需求摘要 API | 拒绝                 | 拒绝                                     | 沿用原授权摘要，新增受限文本不透传 | 不提供   |

新 SourcingDemandView 将采购 title/description 投影为 sharedTitle/sharedSummary，采购响应根本不含 customer/customerId/requesterUserId/客户售价/运营原文。查询搜索只在当前投影标题和编号内执行，不能用受限标题探测。客户候选目录仅运营可读，列表不提供客户筛选。

明细、候选、跟进均显式字段投影，拒绝通过原始对象新增属性绕过隔离；采购历史差异使用共享字段白名单，受限内容单独更新时不向采购返回该事件。事件不携带通用原始快照。按当前可见明细过滤域、按当前可见渠道过滤匹配历史；旧 getDemand 仍返回原白名单摘要与关联基础字段，不透传新增 assessment 或运营文本。前台/测试/运维无法通过新详情获得目标折扣。

所有写入服务层重新检查角色、域、记录、主单版本与会话有效性；切换身份/域会撤销旧 API 写能力。混合域主单资料及状态操作需全部明细域授权，防止用部分视图覆盖隐藏明细。共享说明明确分级，不宣称对自由文本自动判断保密性；生产共享文本审查、附件、导出、服务端审计及防篡改策略仍需后端与独立需求确认。只使用模拟资料。

寻源重置仅双域运营全部域视角二次确认。被寻源候选引用的新增渠道（含已排除）阻止局部渠道重置；不静默删除另一个模块记录。细粒度需求分配/采购负责人规则待确认，不按客户或供应商负责人自行扩权。
